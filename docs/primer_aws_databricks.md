## 1 · 云是什么

### 为什么公司不自己买服务器

以前公司要处理数据，得自己买服务器、放进机房、找人维护。买少了不够用，买多了闲着浪费。

**云**就是：亚马逊（AWS）、微软（Azure）、谷歌（GCP）这几家公司建了巨大的机房，把计算和存储**按用量出租**。用多少付多少，几分钟就能"租"到一台电脑，不用了立刻退掉。

现在几乎所有公司的数据和 AI 系统都跑在云上。这就是为什么招聘要求里到处写 AWS / Azure。

### 三个最基础的词

| 词 | 是什么 | 比喻 | 我们的 |
|---|---|---|---|
| **账号**（account） | 你在 AWS 的"公司户头"，所有资源和账单都挂在这里 | 一个公司的营业执照 | `186972156153` |
| **区域**（region） | 机房所在的城市。数据放在哪个区域，就物理存在那个城市 | 仓库开在哪个城市 | `eu-central-1`（法兰克福） |
| **资源**（resource） | 你租的每一样东西：一个仓库、一把钥匙、一个程序 | 租来的每件设备 | 4 个桶、1 把密钥…… |

**为什么选法兰克福**：离巴塞罗那近（快），在欧盟（数据合规），服务最全。

## 2 · AWS：只讲我们要用的

AWS 有两百多个服务，公司里一个数据 / AI 工程师常用的就下面这些。

### 2.1 门禁：IAM（谁能做什么）

**IAM**（Identity and Access Management）是 AWS 的门禁系统。每一个操作（建仓库、读文件、删东西）AWS 都会先问："你是谁？你有没有这个权限？"

| 概念 | 是什么 | 比喻 |
|---|---|---|
| **root 用户** | 注册账号时的那个身份，权限无限，**不能日常用** | 房产证原件 |
| **IAM 用户** | 给"人"用的身份，有密码，能登录网页 | 员工工牌。我们的 `pipi-admin` |
| **IAM 角色**（role） | 给"程序"用的身份，**没有密码**，谁需要谁临时"扮演"它 | 临时通行证：用完就收回 |
| **策略**（policy） | 一张写着"允许做什么、不允许做什么"的清单，贴在用户或角色上 | 工牌上印的"可进入区域" |

**最重要的原则：最小权限**。每个人、每个程序只给它干活必需的权限。程序被黑了，损失也有限。

**为什么程序用角色不用用户**：用户有长期密码，一旦泄露，别人可以一直用。角色只发**临时凭证**（几小时后自动失效）。公司里所有自动化程序都用角色。

**我们项目里**：00 号建了你的 `pipi-admin` 用户；01 号建了 CI 用的角色；后面每个自动运行的程序（Lambda、Airflow）都会有自己的角色。

### 2.2 仓库：S3（存文件的地方）

**S3**（Simple Storage Service）是 AWS 的存储服务，几乎所有数据最终都放在这里。

| 概念 | 是什么 |
|---|---|
| **桶**（bucket） | 一个仓库。名字全球唯一（所以我们的名字里带账号 ID） |
| **对象**（object） | 仓库里的一件东西，就是一个文件 |
| **键**（key） | 文件的"路径"，比如 `proteome/2026-10/data.tar.gz`。S3 其实没有真的文件夹，斜杠只是名字的一部分 |

**为什么公司把数据都放 S3**：
- **几乎无限大**：放 1 GB 和放 1 PB 用法一样
- **便宜**：每 GB 每月约 2 美分
- **非常可靠**：AWS 承诺数据几乎不会丢
- **所有服务都能读**：Databricks、SQL 查询、程序、AI 服务都直接读 S3

**桶上常开的设置**（01 号都配了）：
| 设置 | 作用 |
|---|---|
| 禁止公开访问 | 互联网上任何人都读不到 |
| 加密 | 硬盘上的数据是加密的 |
| 版本控制 | 文件被覆盖或误删，旧版本还在 |
| 生命周期 | 定期自动清理（比如临时文件 7 天删） |

### 2.3 钥匙保管：KMS

**KMS**（Key Management Service）保管加密用的钥匙。S3 加密数据时用 KMS 里的钥匙，钥匙本身永远不离开 KMS。

**为什么不让 AWS 自动加密就好**：自己的钥匙（每月 1 美元）可以控制**谁能用钥匙**。数据就算被人拿到，没有钥匙的权限也打不开。医药、金融公司通常要求这样做。

### 2.4 跑程序的三种方式

数据放好了，总得有程序去处理它。AWS 上跑程序主要有三种：

| 方式 | 是什么 | 比喻 | 适合 | 计费 |
|---|---|---|---|---|
| **EC2** | 租一台完整的虚拟电脑 | 租一间办公室，24 小时开着 | 长期运行的大程序 | 开着就收钱 |
| **容器**（ECS / Fargate） | 把程序和它需要的一切打成一个包，在 AWS 上运行 | 外卖盒：整包拿走就能吃 | 中等任务、需要固定环境的程序 | 按运行时间 |
| **Lambda** | 只上传一个函数，**有事件来才运行**，跑完就停 | 按次叫的跑腿：有活才来，没活不收钱 | 短小任务：一个文件到了处理一下、回答一次 API 请求 | 按调用次数和毫秒 |

**Serverless（无服务器）** 指的就是 Lambda 这一类：你不用管机器，没人用的时候一分钱不花。我们项目里，对外的查询服务（10 号）和新文件到达时的自动检查（03 号）都用 Lambda。

**ECR** 是存放"外卖盒"（Docker 镜像）的仓库。02 号会做出我们的第一个镜像。

### 2.5 事件：让 AWS 自己干活

AWS 里很多东西会"发出事件"，比如"S3 里来了一个新文件"。你可以设置"一有这个事件，就自动运行某个 Lambda"。

**为什么重要**：数据管道不需要有人盯着。文件一上传，检查、登记、通知自动发生。这叫**事件驱动**（event-driven），是 AWS 上数据接入的标准做法。我们在 03 号用。

### 2.6 对外窗口：API Gateway

**API** 是程序之间的"窗口"：别人发一个请求（"给我 TP53 的 R175H 的预测分数"），你返回一个结果。

**API Gateway** 是 AWS 的"前台接待"：接收外面的请求、检查身份、限制频率，再转给后面的 Lambda 处理。我们在 10 号用它把预测结果开放出去。

### 2.7 直接对文件写 SQL：Athena + Glue Catalog

S3 里存的是文件，不是数据库。但很多时候你想直接用 SQL 查它们。

- **Glue Data Catalog**：一本"目录"，记录"S3 的这个位置是一张表，它有哪些列、什么类型"
- **Athena**：按目录直接对 S3 里的文件跑 SQL，**不用启动任何机器**，按扫描的数据量付费（每 TB 5 美元）

我们在 10 号用它们查导出的预测结果。

### 2.8 其他几个

| 服务 | 是什么 | 我们哪里用 |
|---|---|---|
| **Secrets Manager** | 保险箱：存密码、令牌，程序运行时再取，**不写在代码里** | 06 号：存 Databricks 的访问令牌 |
| **CloudWatch** | 监控：收集程序日志、画指标图、出问题时报警 | 03 号起看日志；13 号设报警 |
| **CloudTrail** | 监控录像：记录账号里每一个操作，谁、什么时候、做了什么 | 00 号看过 |
| **Budgets** | 花费报警 | 00 号设了 10 / 25 / 50 美元三档 |
| **Bedrock** | 租用大模型（Claude、Llama 等）和配套的 RAG、Agent 工具，按调用付费 | 11、12 号 |

## 3 · Databricks：数据平台

### 3.1 它是什么，公司为什么用它

**Databricks** 是 Apache Spark（处理大数据的引擎）的创始团队开的公司。它把"处理大数据、写 SQL、训练模型、管理数据权限"放在**一个平台**里，装在公司的云账号上面。

**为什么公司用它，而不是自己拿 AWS 的零件拼**：
- **一个地方做所有事**：数据工程师、分析师、数据科学家在同一个平台上协作
- **统一的权限和目录**：哪张表谁能看、数据从哪来到哪去，一个地方管
- **不用自己维护 Spark 集群**：点几下就有算力，用完自动关

**你在 dsm 课程里用过它**。这次我们用的是 **Databricks Free Edition**：Databricks 公司替你托管的免费工作区，不占用你的 AWS 账号。

### 3.2 核心概念

| 概念 | 是什么 | 比喻 |
|---|---|---|
| **工作区**（workspace） | 你登录后看到的那个网页环境，所有东西都在这里 | 你的车间 |
| **算力**（compute） | 真正干活的机器。Free Edition 只有 **serverless**：要用时自动分配，不用时自动释放 | 车间里的机器，按需开关 |
| **SQL warehouse** | 专门跑 SQL 的算力，给 SQL 查询和 dbt 用 | 专门做 SQL 的机器 |
| **notebook** | 写代码和说明的页面，一格一格运行。和 Jupyter 很像 | 实验记录本 |

### 3.3 Unity Catalog：数据的目录和门禁

Databricks 里所有数据都按**三级目录**组织：

```
catalog（目录）     qafi                    ← 一个项目或一个环境
  └─ schema（库）   bronze / silver / gold  ← 数据的不同加工阶段
       ├─ table（表）    proteome_predictions
       └─ volume（卷）   raw_files           ← 放原始文件的地方（不是表）
```

完整的表名就是 `qafi.silver.proteome_predictions`。

**Unity Catalog** 就是管这套目录的系统，同时负责：
- **权限**：谁能读哪张表
- **血缘**（lineage）：这张表是从哪几张表算出来的，自动记录
- **审计**：谁什么时候读了什么

### 3.4 Delta Lake：Databricks 的表格式

Databricks 里的表，底下是一堆文件（Parquet 格式）加一本"变更日志"。这种格式叫 **Delta**。

日志带来的好处：
| 好处 | 意思 |
|---|---|
| **ACID** | 写到一半失败，不会留下半成品，要么全成功要么全不算 |
| **time travel** | 可以读"昨天这张表长什么样"，改错了能回滚 |
| **schema 检查** | 列的类型不对，写入会被拒绝，脏数据进不来 |
| **MERGE** | 可以"有则更新、无则插入"，增量更新数据 |

dsm 第 3 课你在本地用过这些功能，Databricks 里是一样的。

### 3.5 Medallion：bronze / silver / gold

公司里几乎都这样分层整理数据：

| 层 | 放什么 | 比喻 | 我们的例子 |
|---|---|---|---|
| **bronze** | 原样导入，不改内容 | 刚进货的原材料 | 86 GB 压缩包读进来的原始表，**带着 99% 的重复行** |
| **silver** | 清洗过：去重、改对列名、类型正确 | 洗好切好的食材 | 去掉重复、修正 `GeneID` 列名后的全蛋白组表 |
| **gold** | 给人直接用的结果 | 端上桌的菜 | 每个蛋白、每个变异的最终预测分数 |

**为什么分层**：出了问题可以从上一层重新算；不同的人用不同的层；原始数据永远保留。

### 3.6 Jobs：让数据管道自动运行

**Lakeflow Jobs**（以前叫 Workflows）是 Databricks 的定时任务系统：把几个 notebook 或 SQL 按顺序串起来，定时运行，失败了自动重试、发邮件。

**Airflow** 是另一个更通用的编排工具，能调度 Databricks、AWS 和其他系统。公司里两个都常见：Databricks 内部用 Jobs，跨系统用 Airflow 触发。我们在 06 号两个都用。

### 3.7 MLflow：机器学习的记录本和模型仓库

训练模型时会试很多次：不同的特征、参数、数据。**MLflow** 记录每一次实验的参数、指标和生成的模型，让你能比较、能复现。

训练好的模型**注册**到 Unity Catalog 里，像表一样有名字、版本和权限。给某个版本贴上 `champion`（冠军）标签，就表示"线上用的是这个"。我们在 07–09 号用。

### 3.8 dbt：用 SQL 写数据转换

dsm 课程里你学过：dbt 让你只写 `SELECT`，它负责建表、按依赖顺序运行、测试、生成文档。在 Databricks 上用法完全一样。05 号用。

## 4 · AWS 和 Databricks 怎么配合

### 公司里

Databricks **装在公司的 AWS 账号里**：
- 数据实际存在**公司的 S3** 里，Databricks 读写这些桶
- 权限通过 **IAM 角色**授予 Databricks
- Databricks 之外的东西直接跑在 AWS 上：对外 API、网站、GenAI 应用、其他系统的数据进货口

### 我们的项目

Free Edition 是 Databricks 托管的，没有装在你的 AWS 账号里。所以两边各管一摊：

| 环节 | 在哪 | 章节 |
|---|---|---|
| 账号、权限、基础设施、CI | AWS | 00–02 |
| 原始数据进货、归档 | AWS（S3 + Lambda） | 03 |
| 整理数据、建表、训练、打分 | Databricks | 04–09 |
| 对外查询服务 | AWS（S3 + Athena + Lambda + API Gateway） | 10 |
| AI 问答和 Agent | AWS（Bedrock） | 11–12 |

## 5 · 工程化的几个词

| 词 | 是什么 | 公司为什么需要 |
|---|---|---|
| **Git / GitHub** | 记录代码每一次修改的工具 / 存放代码的网站 | 谁改了什么、为什么改，都有记录；可以回滚；多人协作 |
| **测试** | 自动检查代码结果对不对的小程序 | 改了一处，自动知道别处有没有坏 |
| **CI**（持续集成） | 每次提交代码，GitHub 自动跑检查和测试 | 坏代码进不了主分支 |
| **Docker** | 把程序和它需要的一切打成一个包（镜像） | 我电脑上能跑 = 云上能跑 |
| **Terraform** | 把云资源写成代码（"图纸"） | 能审查、能重建、能一键删除 |
| **OIDC** | CI 访问 AWS 时，用临时通行证代替密码 | 不在任何地方存长期密码 |
